# Page Recipes

These are composition recipes, not rigid templates. Replace nouns, fields, metrics, and data with domain-realistic content.

## Dashboard / overview

Use stable app navigation + concise page header + a small KPI row + one dominant analysis/list surface + one secondary insight/task surface. Do not make every number a card. Prefer one or two charts only when the relationship is genuinely visual.

## List / management

Use page title + primary action + search/filter controls + list/table + row actions + contextual edit/create overlay. Keep the user on the page and update mock state after save/delete.

## Settings / preferences

Group related controls into 3–5 sections. Use native form labels/help/validation. Keep save behavior obvious. For mobile, prefer cell/form sections and a sticky/fixed action only when needed.

## Detail / profile

Use an identity/header block, concise status/meta, then grouped content. Secondary edit actions should open a native dialog/drawer/sheet rather than navigating to a fabricated route.

## AI / assistant workspace

Separate context/input, main conversation/result, and optional supporting evidence/settings. Make prompt submission or mode switching work locally. Avoid decorative AI gradients unless the product concept specifically calls for them.

## Commerce / service mobile flow

Use native mobile navigation, media/summary area, price/status, options, trust/service information, and a thumb-reachable bottom action. Prefer sheet/popup pickers over desktop dropdown behavior.

## Landing / launch page

Use one strong proposition, short proof/value sections, a product preview or workflow, and one primary CTA. Keep application UI and marketing UI visually distinct.
