# Mock Data Rules

Mock Data 是原型设计的一部分，而不是填空。

## 1. 基本要求

一组数据至少体现 4 类差异：

- 名称长短差异
- 状态差异
- 时间差异
- 数值或业务阶段差异

建议列表默认 6～10 条数据，足以形成真实页面密度。

## 2. 数据必须符合业务

不要使用：

- Test 1 / Test 2
- User A / User B
- Company A
- Lorem ipsum
- 1,2,3 机械递增数字

应该使用自然业务数据，例如：

- 「杭州知行资产管理有限公司」
- 「2026 夏季投资策略线上发布会」
- 「AI 财经直播拆条 · 8 月 10 日」

## 3. 状态分布

不要所有数据都是“正常”。

例如任务：

- 运行中
- 排队中
- 已完成
- 失败
- 已暂停

例如客户：

- 新线索
- 跟进中
- 已成交
- 暂停跟进

## 4. 时间

以当前产品语境生成自然时间：

- 10 分钟前
- 今天 09:42
- 昨天 18:20
- 2026-08-06

同一表格不要全部用完全相同格式，除非产品规范要求。

## 5. 数值

数值要有量级与关系：

- 观看人数 18,426；报名人数 7,812
- 完成率 92.4%
- 费用 ¥12,860

避免每个值都是 100、200、300。

## 6. 边界状态

有助于表达产品价值时，加入 1～2 个异常：

- 分析失败
- 审核待补充
- 服务告警
- 内容过期

不要为了丰富而强行制造异常。

## 7. 字段相关性

字段之间要逻辑一致：

- “已结束”的直播时间应在过去
- “运行中”的任务进度不能是 100%
- “未开始”的活动观看人数通常为 0
- 高风险对象应有对应风险标签或原因
