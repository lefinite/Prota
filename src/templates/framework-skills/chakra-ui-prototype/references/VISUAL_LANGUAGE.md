# Visual Language — Chakra UI

## Intended character

Use semantic tokens, restrained surface contrast, clear focus states, generous-but-not-loose spacing, and responsive layout primitives. Chakra can feel warm and approachable without becoming playful. Prefer token-driven product identity over heavy custom CSS.

## Hierarchy

- Give the page one dominant region and one dominant action.
- Use 2–3 surface levels maximum.
- Keep metadata quieter than main content; reserve destructive/status colors for state.
- Prefer spacing/alignment to excessive borders.

## Spacing

- Use the framework's native spacing scale or established project tokens.
- Vary section rhythm deliberately instead of using the same gap everywhere; protect scanability in dense tables/forms.

## Typography

- One coherent font system by default.
- Keep application titles compact; use larger type only for genuine hero/KPI emphasis.
- Maintain readable secondary metadata and consistent number alignment.

## Color

- One product accent plus framework neutrals.
- Status colors mean state, not decoration.
- Do not implement multiple themes unless requested.

## Motion

- Prefer built-in overlay/tab/list transitions.
- Add motion only when it clarifies state change.

## Device rule

Prioritize stable navigation, efficient horizontal space, keyboard/mouse density, and scanable data hierarchy.
