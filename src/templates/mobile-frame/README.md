# Mobile Frame Template

这是移动端原型页面的基础手机外框模板。

新增页面不只是复制一个空壳，而是要在统一的手机设备框架里，快速表达一个真实的业务场景、功能入口或操作流程。

## 模板定位

- 统一所有 Demo 的移动端观感，包括手机外壳、状态栏、安全区、滚动容器和基础字号。
- 保证每个页面版本目录完全自包含，方便单独预览、分享、截图和生成 PRD。
- 给新增页面提供稳定骨架，但不限制页面内容风格；页面设计应服务当前项目和功能概念。

运行时不要直接引用本目录文件。所有新增页面都应复制本模板到自己的版本目录，再独立维护 `index.html`、`styles.css`、`app.js`，避免违反 Demo 页面“每个版本目录完全自包含”的规约。

## 页面创建原则

新增页面必须先明确“这个页面在当前项目里解决什么问题”，再开始填充界面。

- 内容要围绕具体场景展开，例如首页、登录、列表、详情、设置、反馈、数据看板、任务流程等。
- 首版就要做成可运行 Demo，不能只保留占位标题和空状态。
- 页面应包含真实信息层级、操作反馈和可点击交互。
- 页面文案默认使用中文，除非当前需求明确要求英文或中英混排。
- 页面独有设计可以大胆，但必须保留统一手机框架。

## 目录规约

新页面固定创建到：

```text
src/pages/{project_id}/{page_id}/v1/
```

其中 `v1/` 至少包含：

```text
index.html
styles.css
app.js
frame-fit.js
```

每个版本目录只能引用本目录内自己的 `./styles.css` 与 `./app.js`，不要跨页面或跨版本引用样式与脚本。

## 使用方式

1. 创建 `src/pages/{project_id}/{page_id}/v1/`
2. 将本目录的 `index.html`、`styles.css`、`app.js`、`frame-fit.js` 复制到新页面 `v1/`
3. 替换 `index.html` 中 `.app-content` 内部内容
4. 保留 `.demo-stage`、`.phone-shell`、`.phone-screen`、`.status-bar`、`.app-content` 这套基础结构
5. 在 `styles.css` 中保留 `Shared mobile frame` 区域，只在 `Page content` 区域追加页面样式
6. 在 `app.js` 中保留状态栏时间逻辑，再追加当前页面交互
7. 同步注册页面入口，确保 Portal 可以在 `<iframe>` 中加载该页面

## 交付检查

新增页面完成后至少确认：

- 页面可以在移动端手机框架中完整显示
- 首屏不是空模板，有明确的项目场景和功能目标
- 关键按钮、选项、切换或输入有即时反馈
- `v1/` 目录自包含，没有引用模板目录或其他版本资源
- 页面入口已写入项目配置与 Portal 默认数据

## 预览尺寸适配

保留 index.html 末尾的本地 `./frame-fit.js` 引用。电脑上按预览区域等比例缩放整台手机，最大 100%，四周留 24px；窄电脑窗口仍保留外框。窄屏触摸设备上去掉外框并铺满 iframe；手机内嵌的 Demo 也铺满内部区域，避免重复缩放。Prota 和分享页使用同一套规则，窗口和抽屉尺寸变化后自动重算。

脚本只控制手机框几何，不修改内容字号或业务交互。每个版本保留自己的脚本副本，不引用其他版本。规范源文件为 `tools/mobile-frame/frame-fit.js`；修改后运行 `node tools/mobile-frame/sync.mjs` 同步现有副本和 Portal 后备实现。
