# 启动与链接分享

## 双击即可开始

先解压完整产品文件夹，再双击对应的启动入口：

| 系统 | 双击入口 |
| --- | --- |
| macOS | **Prota.app** |
| Windows 10/11 x64、Windows 11 ARM64 | **Prota.exe** |

Windows 11 ARM64 可以运行 x64 启动入口，下载的 Node.js 和 Python 则使用 ARM64 原生版本。暂不支持 32 位 Windows。请将启动入口和 `scripts`、`server` 等目录一起保留，不要单独移走，也不要从压缩包内直接运行。Mac 原来的 `start-portal.command` 也会转到后台启动器。

- 环境和依赖齐全时，直接打开工作台，不显示安装向导，不在每次启动或分享时升级工具。
- 首次缺少组件，或产品更新后依赖发生变化时，准备窗口才显示实际步骤：运行环境、Python 环境、产品依赖、打开工作台。
- 程序会下载并校验适合当前电脑的运行环境，安装到本机用户目录；业务项目不会放入运行环境目录。
- 安装产品依赖时会自动获取当时最新版 Vercel CLI，放在产品内部。用户不需要安装或操作命令行工具。
- 准备失败时点击「重试」。正常运行后不需要保留终端窗口；关闭浏览器页面不会删除项目或分享。

首次准备需要联网和可写的产品文件夹。Mac 和 Windows 都可能显示下载应用的系统信任提示；启动器目前没有平台发行证书签名。如果公司设备策略禁止运行，应由管理员按公司规定处理，启动器不会修改系统安全策略或请求管理员权限。

新老用户使用相同入口。再次启动会沿用已有工作区、设置和 Vercel 登录；更新产品时替换产品文件并再次双击即可，业务数据仍在独立工作区中。启动器会检查依赖变化，但不会自动下载产品源码更新。不要用一个空白工作区覆盖现有项目。

准备失败时，Windows 诊断位于 `%LOCALAPPDATA%\Prota\`，Mac 诊断位于 `~/Library/Caches/Prota/`；窗口中会给出日志位置。

## 连接 Vercel

1. 打开产品的「设置 → 分享配置」，选择 **Vercel 自动分配地址**。
2. 点击 **连接 Vercel**。若需要登录，程序会打开 Vercel 官方授权页面；你只需在浏览器完成登录或注册、授权。
3. 返回产品即可看到准备进度。Prota 会自动准备分享项目、获取正式 `vercel.app` 地址，并保存设置。
4. 页面提示连接成功后，在原型中选择「链接分享」，等待发布成功，再把链接发给别人。

不需要手动创建 Vercel 项目、复制 Token、填写分享地址、配置 GitHub 或输出目录，也不需要可用的 AI 模型才能连接。已有有效登录时自动沿用，不会反复要求授权。

已有分享项目优先复用，原域名、链接与访问权限保持不变。原项目无权访问或原域名缺失时会报错，不会悄悄创建替代项目。新建项目的初始化只发布一张空白欢迎页，不上传你的业务工作区；新项目的分享链接面向收到链接的人访问。

登录或授权过期时，重新点击连接。若浏览器未自动打开，点击进度区域里的「打开 Vercel 授权页面」。授权过期、账号限制、网络或权限不足时，产品会显示失败原因，可以重试或取消；不会自动购买付费服务。

## 自有域名可选

默认地址已经能分享，无需购买域名。若需要自己的域名，选择「使用自有域名」，填写后点击「绑定域名并连接」，设置会自动保存。产品会自动将域名添加到 Vercel 项目，并显示 Vercel 返回的 DNS 记录。

如果域名托管在其他服务商，你需要到该服务商添加这些记录，然后在产品里点击「重新检查 DNS」。Prota 无法仅凭 Vercel 授权修改其他服务商的 DNS。验证通过前不会替换当前可用分享配置。

## 有效期与密码

单页和文件夹均使用「链接分享」。发布前选择 1 天、7 天、30 天或永久有效，默认 30 天；可开启访问密码（4–128 个字符），开启时自动生成 4 位密码，也可手动修改。点击创建时先复制包含链接、到期时间和密码的分享文本，再开始发布；发布成功后本次内容和权限生效。未设置密码或永久有效时省略对应字段。重新分享同一页面版本或文件夹会更新原链接的内容和权限，不生成独立的权限副本。

有效期从创建分享时开始计算，以云端时间校验。分享 HTML、原型、文档、素材和 ZIP 都放在 Vercel Function 私有目录中，访问资源必须持有该分享的有效会话；两种链接路径遵循同一策略。密码通过随机盐和 scrypt 派生，明文不会写入分享 HTML、URL、浏览器存储或发布清单；为便于以后复制完整信息，密码单独保存在本机工作区的 `data/share-passwords.json`，仅文件所有者可读写，不随分享部署上传。有效期和密码保护仅适用于链接分享，旧的本机／公网入口不提供这些选项。

验证成功后，会话最多保留 24 小时，并受分享有效期限制。密码校验失败有单个函数实例内的频率限制；它不能替代平台防火墙的分布式防护。重新发布后的权限变更会使原会话失效。发布失败时，线上保留上次成功部署的内容和权限，其他未选中的分享也沿用原策略。

历史分享首次迁移时保持原来的永久有效、无需密码；需要保护时重新分享并设置权限。新策略仅对新发布的部署生效，无法撤回接收者已下载的文件，也不会自动修改或删除 Vercel 历史部署。若旧部署曾公开敏感内容，需单独清理旧部署及其独立地址。

验证入口使用独立的 Prota 品牌页面：守护分享小狗、密码错误小狗和休息状态分别对应等待验证、密码错误和分享过期。品牌标识与小狗内嵌在页面中，验证前即可显示，不需要开放业务素材的访问权限。更新验证页后，已部署的线上分享需重新发布才会应用新外观。

## 点击分享后的数据链路

产品内点击分享 → 本机读取独立业务工作区 → 生成分享页、资源和访问策略 → 组装独立 Build Output 目录 → 产品内部 Vercel CLI 直接上传 → 原 Vercel 项目与域名 → 云端验证有效期与访问密码 → 访问者打开链接。

GitHub 只维护产品代码，不参与这条分享链路。访问者从 Vercel 获取内容，无需你的电脑保持在线。

发布目录包含上次成功发布的快照，再叠加本次选中的页面版本、文档和引用素材。单页分享还有 ZIP 下载包。当前实现包含页面标注、PRD 等文档内容；选中版本按整个版本目录复制，并非只有截图或当前 HTML。写入页面或文档的敏感信息不会自动脱敏。

其他页面保留上次发布的内容，不同步未选中的本地修改。项目总索引、Agent 会话、个人设置、模型连接配置和原始附件目录不会作为目录整体发布；被原型引用的素材仍可能随分享上传。

首次没有 `data/published-static` 快照时，会导入工作区中已生成的所有静态分享。本地快照保存在业务工作区，不进入产品仓库。

产品保留 `/shares/文件名.html` 和 `/文件名.html` 两种路径。每次发布都会新增 Vercel 部署；程序不会自动清理平台历史，本地删除页面也不会自动撤回旧发布内容。撤回与历史清理需要单独处理并核对链接。

技术安装与维护命令仅面向开发者，见[开发安装说明](developer-setup.md)。

实现参考：[Vercel 官方登录](https://vercel.com/docs/cli/login)、[创建项目 API](https://vercel.com/docs/rest-api/projects/create-a-new-project)、[部署 CLI](https://vercel.com/docs/cli/deploy)、[Build Output API 私有函数目录](https://vercel.com/docs/build-output-api/primitives)。

## 查看授权是否生效

分享配置始终显示「Vercel 连接」状态。账号授权、发布状态和生效地址分别展示；切换地址选项只表示当前选择，完成授权与项目关联后才显示「已生效」。打开设置时会读取本机持久配置，并向 Vercel 核验账号、项目权限与域名，不依赖上一次连接任务是否仍在内存中。

授权失效时显示「需重新授权」，网络无法验证时显示「无法验证」；账号已授权但项目未连接、域名待验证时会分别提示。点击「检查状态」可重新核验。自有域名配置由内置服务直接执行，不生成 Prota Prompt，也不要求用户把配置指令发送给 AI。
