# 统一设置与外部工作区：设计及实现记录

日期：2026-10-21。状态：用户已确认 B「统一设置窗口」，已实现；按后续反馈改为纯齿轮入口，沿用 Portal 视觉变量与 SVG 图标。

已补充可点击的结构对比样机：`design-previews/2026-10-21-unified-settings/index.html`。
四种组织方式分别为设置目录、统一窗口（推荐）、独立页面与侧边抽屉。
样机保留为历史结构对比，不操作真实目录或配置。正式界面由 `portal/modules/settings/` 实现，不沿用样机的独立配色。

## 目标与范围

在项目列表界面的右上角提供「设置」入口，集中管理存储位置、分享配置和模型配置。
窗口名为「设置」，说明为「工作区与应用偏好」；各分类分别注明作用范围。
此项为 Portal 功能调整，不新增 Demo 页面。工作区切换读取所选位置的项目索引，不向现有项目注册测试页面。

## 现状证据

| 内容 | 当前实现 | 整合时的影响 |
| --- | --- | --- |
| 列表入口 | `portal/index.html` 的 `projectsHomeView`，顶部主导航位于 `content-header` | 入口放在项目列表顶部右侧，不混入项目卡片操作 |
| 分享入口 | 分享菜单内的 `shareSettingsBtn` | 保留为快捷入口，直接定位到分享配置 |
| 分享界面 | `shareSettingsModal`，表单与右侧配置指南组成双栏 | 保留表单；指南改为按需展开，避免默认占去半个窗口 |
| 分享保存 | `portal/shell.js` 的 `saveSettings()`，调用 `/api/settings` | 继续使用原接口；现有成功后关闭弹窗的行为需改为保留设置窗口 |
| 模型界面 | `agentConfigModal`，服务商列表与详情组成双栏 | 必须给模型编辑保留足够宽度，避免外层导航导致三栏拥挤 |
| 模型状态 | `portal/agent/provider-config.js` 的配置存储对象 | 保留服务商实例、当前启用项和选中项的区分 |
| 模型保存 | `saveActiveProvider()`、`persistAgentProviderConfig()`，调用 `/api/agent-provider-config` | 继续复用现有存储与接口，不创建第二份配置 |
| 模型入口 | 模型菜单的设置操作、`openAgentConfigModal()` | 都应转到统一设置的模型项，不能同时打开旧弹窗 |

当前分享界面为浅色，模型界面为深色，两者的标题、遮罩和按钮也不一致。
Portal 的基础配色为浅灰 `#f8f9fb`、白色、正文 `#1a1d24`、次级灰 `#6b7280`、强调色 `#6366f1`、边框 `#e5e7eb`。
基础间距沿用现有界面的 8 / 12 / 16 / 24 / 32 px；中文界面使用系统无衬线字体。

## 推荐结构

采用一个设置窗口、三项分类导航，在窗口中直接编辑。
复用原有表单能力与业务逻辑，统一容器、视觉和关闭规则。
不采用设置目录打开旧弹窗的层层跳转，也不另建一份配置数据。

| 区域 | 内容与行为 |
| --- | --- |
| 项目列表右上角 | 纯齿轮图标，复用现有顶部图标按钮；保留「设置」tooltip 与无障碍名称 |
| 窗口头部 | 标题「设置」、说明「适用于所有项目」、关闭按钮 |
| 分类导航 | 存储位置、分享配置、模型配置，选中项有明确状态 |
| 存储位置内容 | 当前工作区路径、内容概况、更改位置；提供迁移当前内容、打开已有工作区、新建工作区三种明确动作 |
| 分享内容 | 静态域名、Vercel 自动部署、自动配置入口、按需展开的配置指南 |
| 模型内容 | 服务商管理、API Key、Base URL、模型选择与拉取、高级选项、现有连接反馈 |
| 底部操作 | 各分类独立保存，并显示保存中、成功或可操作的错误信息 |

不新增总览页。首次从列表进入时展示存储位置；原有快捷入口始终直接定位到对应分类。
切换分类保留尚未保存的表单草稿；关闭窗口或切换模型服务商涉及丢弃草稿时，明确提供保存、放弃与继续编辑。
切换分类本身不保存配置，不触发模型启用操作。
保存模型与启用模型继续区分，避免用户只是修改配置就改变当前会话所用模型。

模型内容避免三栏挤压：统一窗口提供充足桌面宽度；中等宽度下将服务商列表收为选择控件。
窄屏分类改为顶部切换，表单单列，窗口高度受可视区域约束，操作区保持可达。
指南优先在当前内容区展开，不能继续叠加第三个固定宽度侧栏。

## 视觉读取

面向原型使用者的工具设置界面，强调清晰、稳定，延续现有浅色工作台。
视觉冒险度 3/10、动效强度 2/10、信息密度 6/10。
另一种可讨论方向为紧凑的深色工具窗口；其代价是与浅色项目列表产生更明显的上下文切换。

## 后续实现验收要求

1. 项目列表右上角可以直接进入设置，包含存储位置、分享配置与模型配置三个分类。
2. 原分享与模型快捷入口均进入同一窗口并定位准确，页面上只有一个模态交互层。
3. 原有配置能加载；保存继续使用现有接口；失败时保留表单与错误提示。
4. 切换分类保留草稿；关闭与切换服务商不会静默丢弃修改。
5. 模型新增、编辑、删除、拉取模型及当前启用状态继续正常工作。
6. 关闭后焦点回到实际触发入口；支持 Escape、焦点约束及键盘分类切换。
7. 桌面、中等宽度和手机宽度均无横向溢出，指南和长模型名称不会挤坏布局。
8. 不修改既有 Demo，不新增或复制配置数据，保持 `data/projects.json` 与 `portal/shell.js` 的 `defaultData` 不受影响。

以下保留结构诊断与实施边界；操作说明与验证命令见 `docs/workspace-storage.md`。

## 新增范围：程序与项目资产分离

用户补充：首次使用时可以选择一个文件夹，项目相关内容保存到该文件夹中。
此要求覆盖前文“不修改项目注册数据”的初始边界：统一设置入口本身不需修改注册数据，但存储位置功能必须迁移并切换项目索引的读写位置。

### 定义与建议目录

用户选择的是整个工作区的根目录，而非单个项目目录；其中容纳多个项目。
为兼容既有目录约定，工作区内部继续保留 `src/pages/{project_id}/{page_id}/{version}/`。
示例中的 `Prota工作区` 由用户选择，不硬编码为产品默认位置。

```text
用户选择的文件夹/Prota工作区/
  workspace.json             工作区标识与格式版本
  data/
    projects.json            项目、页面、版本、回收站状态
    agent-sessions/          与工作区绑定的会话
    agent-uploads/           会话附件
    agent-checkpoints/       撤销与恢复快照
  src/pages/
    {project_id}/
      {page_id}/
        v1/                  index.html、styles.css、app.js、本地素材、标注
        docs/                PRD、图表、截图及配套素材
  assets/                    经引用审计确认属于项目的公共素材
  shares/                    分享生成物
```

应用代码、内置模板与内置 Skill 保留在程序目录。
程序保存“当前工作区路径”的偏好位于独立的本机应用配置目录，不依赖工作区可访问。
模型密钥属于本机凭证，不随项目资产迁移或导出；其持久化应使用本机凭证存储，不能混入工作区清单。
分享域名等配置与工作区的归属在实现时明确：发布目标建议随工作区保存，模型连接与最近工作区路径属于本机设置。
界面须分别注明作用范围，原先笼统的“适用于所有项目”调整为“管理工作区与应用偏好”。

### 存储位置界面

1. 顶部显示「项目存放位置」及完整路径，长路径允许换行和复制，支持打开所在文件夹。
2. 用简短说明列出会保存的内容：项目页面、素材、PRD、标注、会话与附件。
3. 主操作为「更改位置」，进入明确的“迁移当前工作区”流程；另提供「打开已有工作区」和「新建工作区」。
4. 迁移前显示来源、目标、项目数量与预计大小；统计失败时说明原因，不显示伪造数字。
5. 迁移期间显示准备、复制、校验、切换四个阶段；禁止并发修改源工作区，不能仅靠前端禁用按钮。
6. 失败时保留原工作区为活动位置，给出重试路径；成功后展示新位置，原目录保留，清理为独立操作。

首次运行：显示「选择项目存放位置」。允许新建工作区或打开已有工作区。
检测到当前版本已有项目时，优先提供「迁移现有项目」及「暂时使用原位置」，不得将旧用户直接带进空白工作区。
取消选择不会创建或切换工作区。仅选择文件夹不会立即迁移；迁移前展示具体影响供用户确认。
文件夹选择由本机服务或桌面能力执行；若从远端访问，须明确选择的是运行程序的电脑上的路径，而非访问者电脑的文件夹。

### 迁移与切换规则

- 迁移：校验目标可写、空间与目录关系 → 暂停新写入并等待运行任务收尾 → 复制到暂存目录 → 按文件清单校验完整性 → 发布目标工作区 → 原子更新活动位置 → 恢复服务并刷新列表。
- 迁移必须覆盖回收站内内容和未显示在项目列表中的资产，不能仅按活跃项目索引挑选文件。
- 目标与来源相同、为彼此父子目录、指向程序安装目录或存在不兼容内容时应明确拒绝；解析真实路径以识别符号链接。
- 目标存在已有工作区时引导“打开”，不自动合并或覆盖。
- 首次分离迁移从旧程序仓库中按资产清单复制，不把程序依赖、配置密钥和应用源码一起复制。
- 中断后原工作区仍可用；暂存数据有明确归属，可恢复或清理，不能被误认成完整工作区。
- 切换到已有工作区是另一个动作：加载其自己的索引和会话，隔离浏览器缓存；不将旧工作区的状态写进新目录。
- 工作区离线、磁盘被拔出或无权限时展示“位置不可用”及重新定位入口，禁止静默回落到程序目录或自动初始化空目录。

### 代码影响与兼容边界

已核查的固定路径包括：

| 模块 | 证据与需调整内容 |
| --- | --- |
| `server/bridge.py` | `get_project_root()` 通过 `src/pages` 识别程序根；扫描、CRUD、PRD、标注与资源接口多处直接拼接程序目录 |
| `server/agent-server.mjs` | `ROOT_DIR` 同时充当程序根、项目根和 Agent cwd；会话、附件、快照、文档写入及路径边界均绑定此根 |
| `portal/shell.js` | 项目索引请求、iframe 预览、版本扫描、标注和文档路径使用 `/src/pages/`；生成提示也固定仓库路径 |
| `server/deployer.py` | 发布流程使用独立 Build Output 目录直接部署 Vercel，不提交或推送业务文件 |
| `scripts/` 与 `tools/` | 迭代、删除、截图、绘图与模板同步脚本需要读取当前工作区位置 |
| `AGENTS.md` 与生成 Skill | 既有“同步修改程序中的 defaultData”等约定必须更新，避免生成任务继续写回安装目录 |

建议建立程序根与工作区根两套明确的路径解析，全部文件操作经过统一解析器。
浏览器可以继续使用 `/src/pages/...` 这样的逻辑 URL，由服务映射到当前工作区实际位置，减少既有 Demo 链接破坏。
旧页面对公共素材或模板的相对引用必须扫描并验证；不能假设所有目录已经完全自包含。
路径权限边界需跟随工作区调整，且预览映射不能暴露电脑上的任意路径或本机凭证。
会话和长任务绑定工作区标识，切换期间不得将旧请求结果写入新工作区。
Node 与 Python 服务必须共享同一活动位置与切换状态，不能各自缓存后不同步。
项目索引随工作区保存后，不再在日常操作中修改应用的 `portal/shell.js`。工作区内另有 `portal/shell.js` 元数据快照，其 `defaultData` 与该工作区的 `data/projects.json` 同步。
静态发布使用外部业务工作区与独立发布暂存区，直接部署到原有 Vercel 项目。已移除 Git 发布路径，产品仓库单独管理。

### 新增验收门槛

1. 空目录初始化后能创建项目、页面和迭代版本，实际文件仅进入所选工作区。
2. 迁移后重启仍能打开原项目，预览、素材、PRD、标注、图表、截图、回收站与会话附件均可读写。
3. 两个工作区具有相同项目 ID 时，切换不串数据、不串缓存或正在运行的任务。
4. 无权限、磁盘不足、复制中断、校验失败和目标冲突均不能导致源资产丢失或活动位置提前切换。
5. 程序更新与移动程序安装目录不影响外部工作区，工作区不可用时不在程序目录生成替代资产。
6. 分享生成与发布可以读取外部工作区，凭证不进入项目导出物。
7. 新建和迁移工作区均保留版本目录自包含约束，所有页面配置保留 `targetDevice`。

此需求涉及数据路径与迁移机制，不能以“路径输入框可保存”作为完成证据。
