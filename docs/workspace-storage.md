# 设置与项目存放位置

项目列表右上角的齿轮图标打开统一设置。设置包含存储位置、分享配置和模型配置；原分享菜单与模型菜单中的配置入口也进入同一个窗口。

## 选择存放位置

首次使用会在存储位置中提示选择文件夹；现有用户可以先继续使用原位置。

- **更改位置**：将当前工作区复制到另一个空文件夹，逐文件校验成功后切换。原文件保留。
- **打开已有工作区**：切换到已经初始化的 Prota 工作区，不合并两边的项目。
- **新建工作区**：在空文件夹中初始化新的项目索引，当前工作区保留。

可以使用系统文件夹选择器，也可以填写本机绝对路径。迁移或新建时请选择空文件夹；系统选择器中可以先创建一个新文件夹。检查位置后会显示来源、目标和实际内容，再确认执行。

选择的是运行 Prota 服务的电脑上的文件夹。存储位置管理仅允许从本机访问。

## 哪些内容跟随工作区

工作区保留 `src/pages/{project_id}/{page_id}/{version}/` 结构。项目索引与工作区内 `portal/shell.js` 的 `defaultData` 元数据快照保持同步，程序安装目录中的同名源码不会被外部工作区改写。项目页面、各版本、素材、PRD、标注、图表、截图、回收站记录、会话、附件、恢复快照和分享生成物随工作区保存。

程序、内置模板与内置 Skill 保留在安装目录。模型连接配置保存在本机应用配置目录，不随工作区迁移或发布。分享域名及推送策略保存在各自工作区。

本机使用 `~/.config/prota/workspace.json` 记录当前工作区位置；不需要手动修改此文件。模型配置文件的权限为仅当前用户读写。

## 迁移与恢复

迁移按准备、复制、校验、切换执行。运行中的 AI 任务需要先结束；迁移期间禁止并发写入。复制或校验失败时，继续使用原位置。

目标目录已有内容时不会自动覆盖；已有工作区请使用「打开已有工作区」。磁盘被拔出、路径失效或权限不足时，设置会提示位置不可用，可重新定位；程序不会在安装目录偷偷创建替代项目。

旧的程序内目录仍支持既有访问方式。外部工作区通过本地服务访问，浏览器中的 `/src/pages/...` 预览地址保持不变。

静态云分享沿用原发布远端与分支，在本机配置目录下的独立发布副本中组合程序静态资源与工作区资产，不把项目源码搬回安装目录，也不发布模型凭证。

## 开发验证

```sh
node --test tests/agent-provider-config.test.mjs tests/agent-provider-create-mode.test.mjs
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_workspace*.py' -v
node tests/unified-settings.browser.mjs
```

浏览器验证使用临时工作区、临时端口及占位模型配置，结束后清理；不迁移真实项目，不调用真实模型，不向外部 Git 远端推送。
