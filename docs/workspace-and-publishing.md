# 工作区与直接分享部署

产品程序、内置模板和普通技能在安装目录中维护。业务数据存储在独立工作区，内部目录仍为 `src/pages/{project_id}/{page_id}/{version}/`。在「设置 → 存储位置」中迁移或打开工作区。复制并逐文件校验成功后才切换，原始文件保留供确认和备份。

用户级配置默认保存在 `~/.config/prota/`，可通过 `READIFY_CONFIG_DIR` 更换。`workspace.json` 指向当前工作区；`agent-provider-config.json` 保存本机模型配置；`vercel.json` 只保存项目关联信息。Vercel 凭据使用本机 CLI 登录，不写入项目或工作区。

全新安装会初始化独立的空工作区。旧安装检测到业务项目时，保留迁移入口。`READIFY_WORKSPACE` 可用于指定已有且带清单的工作区。

## 分享

1. 在终端执行 `npx vercel login`。
2. 执行 `python3 scripts/configure-vercel.py --domain share.example.com`，关联该域名所属的现有项目。
3. 在分享设置中开启「生成后自动部署到 Vercel」。
4. 点击静态分享，直接部署独立的 Build Output API v3 目录，不执行 Git 提交或推送。

原有 `/shares/文件名.html` 与 `/文件名.html` 两种路径同时保留。首次切换导入已有静态分享；之后保存上次发布的快照，只更新本次明确分享的页面，避免把其他页面的未分享修改带到线上。运行会话、上传附件目录、项目总索引、个人设置和密钥不会进入发布目录。原型自身引用的素材和模板会随必要资源发布。分享页面内含的业务内容仍会上传至 Vercel，应使用公司允许的托管和访问设置。

Vercel 部署成功并验证链接后，断开原项目的 Git 关联，避免旧仓库部署覆盖直接发布。不要删除历史部署来做首次切换；原部署可用于恢复。部署失败会明确返回失败，不能把本地生成当作线上成功。

## 开源准备

运行 `python3 tools/public-release.py /绝对路径/新的导出目录`。工具按目录和文件白名单导出，不复制 `.git`，不继承任何旧提交历史。检查报告包含公司项目标识、个人路径和已知本机模型密钥的匹配结果，不输出密钥正文。

扫描通过后仍应审阅模板、技能、图片及依赖的来源与分发许可。产品仓库中不得存放业务示例、公司截图、会话日志和工作区备份。不得直接把旧业务仓库改成公开；旧 GitHub 历史和 Vercel 历史部署应按允许的保留要求另行处理。

新产品仓库建议执行 `git config core.hooksPath .githooks`，启用推送前检查。旧业务历史、业务文件和已知密钥命中时会阻止推送。检查不读取或修改远端。
