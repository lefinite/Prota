# 工作区与直接分享部署

产品程序、内置模板和普通技能在安装目录中维护。业务数据存储在独立工作区，内部目录仍为 `src/pages/{project_id}/{page_id}/{version}/`。在「设置 → 存储位置」中迁移或打开工作区。复制并逐文件校验成功后才切换，原始文件保留供确认和备份。

用户级配置默认保存在 `~/.config/prota/`，可通过 `READIFY_CONFIG_DIR` 更换。`workspace.json` 指向当前工作区；`agent-provider-config.json` 保存本机模型配置；`vercel.json` 只保存项目关联信息。Vercel 凭据使用本机 CLI 登录，不写入项目或工作区。

全新安装会初始化独立的空工作区。旧安装检测到业务项目时，保留迁移入口。`READIFY_WORKSPACE` 可用于指定已有且带清单的工作区。

## 分享

1. 双击 `Prota.app`，缺少环境或依赖时会显示准备步骤并自动安装，齐全时直接打开工作台。
2. 在「设置 → 分享配置」点击「连接 Vercel」，按需在浏览器登录授权。
3. 产品自动复用或创建分享项目、获取正式地址并保存，无需手动操作 Vercel 控制台或配置 GitHub。
4. 点击「链接分享」，设置有效期和可选的访问密码，由产品内部已安装的 Vercel CLI 直接部署独立 Build Output 目录。安装依赖时获取当时最新版 CLI，正常启动和分享沿用已安装版本。

原有 `/shares/文件名.html` 与 `/文件名.html` 两种路径同时保留。首次没有发布快照时，导入工作区已生成的所有静态分享；之后保存上次发布的快照，只更新本次明确分享的页面，避免把其他页面的未分享修改带到线上。运行会话、原始上传附件目录、项目总索引、个人设置和模型连接配置不会作为目录整体发布。选中版本目录、页面文档和原型引用的素材、模板会随分享发布；写入这些内容的敏感信息不会自动脱敏。分享页面内含的业务内容仍会上传至 Vercel，应使用公司允许的托管和访问设置。

Vercel 部署成功并验证链接后，断开原项目的 Git 关联，避免旧仓库部署覆盖直接发布。不要删除历史部署来做首次切换；原部署可用于恢复。部署失败会明确返回失败，不能把本地生成当作线上成功。

详细链路、首次项目创建、配置步骤与发布范围见[链接分享配置与数据链路](share-setup-guide.md)。每次分享会新增 Vercel 部署，程序不会自动清理历史；直接删除本地文件不会自动撤回已发布快照；请通过「分享管理」撤回。

## 开源准备

运行 `python3 tools/public-release.py /绝对路径/新的导出目录`。工具按目录和文件白名单导出，不复制 `.git`，不继承任何旧提交历史。检查报告包含公司项目标识、个人路径和已知本机模型密钥的匹配结果，不输出密钥正文。

扫描通过后仍应审阅模板、技能、图片及依赖的来源与分发许可。产品仓库中不得存放业务示例、公司截图、会话日志和工作区备份。不得直接把旧业务仓库改成公开；旧 GitHub 历史和 Vercel 历史部署应按允许的保留要求另行处理。

新产品仓库建议执行 `git config core.hooksPath .githooks`，启用推送前检查。旧业务历史、业务文件和已知密钥命中时会阻止推送。检查不读取或修改远端。

## 分享管理

工作台「分享」下拉菜单中的「分享管理」统一收录当前工作区中的页面、文件夹分享及已发布快照。可以按项目、状态、分享方式筛选，搜索名称、链接或备注，按分享时间或名称排序，复制地址、查看权限、记录接收对象，并导出当前筛选结果的 CSV 清单。状态区分已发布、仅本地、已过期和已撤回；部署失败的新修改不会覆盖清单中的线上版本信息。

支持单条或批量撤回。链接分享先从发布快照中移除选定链接的两种路径、下载包及不再被其他分享使用的页面和文档，再部署到当前固定域名；部署失败会保留本地文件与记录供重试。撤回不删除原始项目，撤回记录保留，重新分享后可再次发布。公网或本机分享撤回会移除本地分享入口。

撤回范围为当前工作区记录和当前配置固定域名。已下载文件、曾配置过的其他域名及 Vercel 历史部署的独立地址不会因此自动失效。管理记录保存在工作区 `data/share-management.json`，随存储迁移一起迁移，不进入分享部署内容；管理 API 仅允许本机同源请求。
